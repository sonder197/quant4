Module 4.1 · Data Analysis Steps
LOS 4.a

Steps in a Data Analysis Project

Identify and explain steps in a data analysis project — for structured data (five steps) and for text data (four modified steps), after a short introduction to big data.

Introduction — what makes data “big”

Big data is characterized by the three Vs: volume, variety and velocity.

📦
Volume (quantity)

The quantity of data. Big data refers to a huge volume of data.

🧩
Variety (sources)

Data collected from various sources: user-generated content, traditional transactional data, emails, images, clickstreams, and so on. Variety creates tremendous opportunities but also concerns such as privacy protection.

⚡
Velocity (speed)

The speed with which data is created and collected (e.g., all the social-media postings created during a specified time interval).

+ Veracity (validity)

When data is used to generate inferences, an additional characteristic must be considered: veracity (validity). Not all data sources are reliable, so the researcher must separate quality from quantity to generate robust forecasts. (Slide: big data is the kind of data that suffers most from veracity problems.)

Module 4.1 · Data Analysis Steps
LOS 4.b

Preparing and Wrangling Structured Data

Describe objectives, steps and examples of preparing and wrangling data: data collection, cleansing, transformation, outliers and scaling.

Data preparation and wrangling is a critical step: it cleanses and organizes raw data for use in a model and takes most of the project’s time and resources.

Step 2 first — data collection (the inputs to wrangling)

  • Once the problem is defined, the data to collect is identified with the help of domain experts.
  • Collection means downloading data from internal and external sources. When accessing a database, take care to ensure data validity.
  • README files associated with a database usually say how, what and where data is stored.
  • External data can be obtained from third-party vendors via an application programming interface (API). It costs money but saves time and money in the wrangling step.
  • Drawback: other market participants can use the same data, diminishing the firm’s proprietary advantage.

3.1 Data cleansing — reducing errors in the raw data

  • Metadata (summary data) about the raw data set can be a starting point for error identification.
  • Observations with erroneous values that cannot be cleansed are dropped.

Wrangling preprocesses data for model use. It has two parts: data transformation and scaling.

Filtration vs. selection

Filtration removes observations (rows); selection removes features (columns). The quiz bank tests this distinction.

Outliers — identify, then handle

  • Identify with statistical techniques, e.g., any value further than 3 standard deviations from the mean.
  • Handle by replacing with algorithm-determined values, or by deleting the observation.
✂️
Trimming

Exclude the highest and lowest x% of observations. The extreme observations are removed.

🪟
Winsorization

Extreme values are replaced by the maximum (or minimum) value allowable for that variable. The observations are kept.

Scaling — converting features to a common unit of measurement

Some ML algorithms (e.g., neural networks, SVM) need features to be homogeneous (feature values in the same range). Two common methods:

📏
Normalization

Rescales variable values between 0 and 1.

🎯
Standardization

Centers the variable at 0 and scales it in units of standard deviations from the mean.

Normalization
normalized Xi = (Xi − Xmin) / (Xmax − Xmin)
Xmin, Xmax = smallest and largest values of the variable. Result lies in [0, 1].
Standardization
standardized Xi = (Xi − μ) / σ
μ = mean of the variable; σ = its standard deviation. Result: mean 0, standard deviation 1.
  • A standardized value of +1.22 means the observation is 1.22 standard deviations above its mean.
  • Unlike normalization, standardization is not sensitive to outliers, but it assumes the variable is normally distributed.
Try it — scaling calculator
Technical aside (not in Schweser)

The curriculum says a standardized variable has a normal distribution with mean 0 and standard deviation 1. For the exam, reproduce that statement (mean 0, standard deviation 1). Strictly, rescaling changes only location and spread, not the shape; the slide’s original / normalized / standardized histograms all show the same right-skewed shape.

Key Concepts — LOS 4.b

Data cleansing deals with missing, invalid, inaccurate and non-uniform values and duplicate observations. Data wrangling (preprocessing) includes transformation (extraction, aggregation, filtration, selection, conversion) and scaling. Scaling converts data to a common unit: normalization rescales to 0–1; standardization centers at mean 0 with standard deviation 1. Unlike normalization, standardization is not sensitive to outliers, but it assumes a normal distribution.

Text preparation (cleansing) — four steps

#StepDetail
1Remove HTML tagsText collected from web pages carries embedded HTML tags that may need removing before processing. A regular expression (regex) is a text string used to identify characters in a particular order.
2Remove punctuationText analysis usually does not need punctuation. Some punctuation (e.g., %, $, ?) may be needed; if so, it is replaced with annotations (textual expressions) for model training.
3Remove numbersDigits are removed or replaced with annotations to tell the ML program that a number is present but its value is not important. If the value is important, it is first extracted via text applications.
4Remove white spacesExtra formatting white space (e.g., tabs, indents) serves no purpose in text processing and is removed.

Tokenization, bag-of-words and the document term matrix

  • A token is a word, and tokenization is the process of splitting a sentence into tokens. “It is a beautiful day.” can be assigned five tokens: it, is, a, beautiful, day.
  • After cleansing and normalizing, a bag-of-words (BOW) procedure collects all the words or tokens without regard to the sequence of occurrence.
  • A document term matrix (DTM) then converts the unstructured data into structured data: each text document is a row, each token is a column, and each cell is the number of occurrences of that token in that document.
Document term matrix — illustrative example
Documentratesrisestocksfall
d1 “rates rise stocks fall”1111
d2 “stocks rise”0110
d3 “rates fall rates rise”2101
d4 “stocks fall rates rise”1111

Rows d1 and d4 are identical: BOW ignores order. Illustrative example (own).

Note the weakness: BOW ignores order, so “rates rise, stocks fall” and “stocks fall, rates rise” produce identical rows. When sequence matters, use N-grams.

N-grams — when word order matters

  • N-grams represent word sequences: a two-word sequence is a bigram, a three-word sequence a trigram, and so on.
  • Sentence “The market is up today” → bigrams: the_market, market_is, is_up, up_today.
  • BOW is then applied to the bigrams instead of the original words.
  • N-gram implementation affects the normalization of the BOW because stop words will not be removed.

Key Concepts — LOS 4.g

Text processing removes HTML tags, punctuation, numbers and white spaces. Text is then normalized by lowercasing, removing stop words, stemming and lemmatization. Text wrangling involves tokenization. N-grams define a token as a sequence of words and are applied when sequence is important. A bag-of-words collects all the tokens in a document. A document term matrix organizes text as structured data: documents are rows, tokens are columns, and cell values are the number of times a token appears in a document.

Module 4.2 · Data Exploration
LOS 4.d

Exploring Structured Data

Describe objectives, methods and examples of data exploration: EDA, feature selection and feature engineering for structured data.

Data exploration evaluates the data set and determines the most appropriate way to configure it for model training. It has three steps:

🔭
1. Exploratory data analysis (EDA)

Look at data descriptors such as summary statistics, heat maps, word clouds. Objectives: understand properties, distributions and other characteristics; find patterns or relationships and evaluate basic questions and hypotheses; plan modeling in future steps.

🎛️
2. Feature selection

Select only the needed attributes of the data for model training. The more features selected, the higher the model complexity and training time.

🛠️
3. Feature engineering

Create new features by transforming (e.g., taking the natural logarithm), decomposing, or combining multiple features.

  • A related term is feature extraction: a feature is created from the data set (e.g., creating a value for age from date-of-birth data).
  • Model performance depends heavily on feature selection and engineering. It is common for the analyst to recursively go back to this step and tweak until performance is acceptable.
Slide: what EDA looks at

The slide’s EDA graphic lists: data distribution, missing data, outliers, correlation, patterns, data types, data visualization, data quality.

4.1 Exploratory data analysis for structured data

Structured data is organized in rows (observations) and columns (features). EDA can be performed for a single feature (one dimension) or multiple features (multidimension). When the number of features is large, dimension reduction models such as principal component analysis (PCA) can facilitate data exploration.

4.2 Feature selection (structured data)

  • Goal: select only the features that contribute to the out-of-sample predictive power of the model.
  • A parsimonious model (fewer features) reduces feature-induced noise and improves prediction accuracy.
  • Requires a good understanding of the business environment and of the interrelationships among features found in EDA. For structured data it is an iterative, methodical process.
  • Features can be given an importance score using statistical methods, then ranked and selected on that score.
  • Dimension reduction algorithms can cut the number of features, reducing processing time during training.

4.3 Feature engineering (structured data)

  • Optimizing and improving the selected features. Training results depend on how the features are presented to the algorithm.
  • Either decompose a feature into multiple features (1 feature → many) or convert an existing feature into a new one.
  • One-hot encoding (OHE) converts a categorical feature into a binary (dummy) variable suitable for machine processing.
  • Aim: make model training faster and easier.

Key Concepts — LOS 4.d

Data exploration involves exploratory data analysis (EDA), feature selection and feature engineering (FE). EDA looks at summary statistics describing the data and any patterns or relationships that can be observed. Feature selection chooses only those features that meaningfully contribute to the model’s predictive power. FE optimizes the selected features.

Features from Text Data

Describe methods for extracting, selecting and engineering features from textual data: term frequency, word clouds, DF, chi-square, mutual information, numbers, N-grams, NER and POS.

Exploring text: summary statistics and word clouds

Unstructured text can be tokenized, and summary statistics can be analyzed:

🔢
Term frequency (TF)

The number of times a word appears in the text.

🤝
Co-occurrence

Where two or more words appear together.

A word cloud is a visual representation of all the words in a BOW, where words with higher frequency have a larger font size. It helps the analyst see which words are contextually more important.

Word cloud — illustrative (the curriculum’s Figure 4.1 is a cloud for an Apple SEC filing)

Feature selection for text — shrinking the BOW

Feature selection means choosing a subset of tokens in the BOW. A smaller BOW makes the model more parsimonious and reduces feature-induced noise; noisy features do not contribute to prediction accuracy.

  • High- and low-frequency words are often eliminated, giving a more concise BOW.
  • High-frequency words tend to be stop words (if not removed during wrangling) or common vocabulary. Low-frequency words may be irrelevant.
  • Bankruptcy-model example: to separate defaulters from non-defaulters, tokens associated with both categories should be removed.
MethodDefinitionHow to read it

Exam tip — NER vs. POS

Both assign tags to tokens (Module Quiz 4.2 Q1 uses this). NER = what kind of entity (ORG, Place, DATE…). POS = grammatical role (NNP, CD, VBZ…). OHE is not a text technique: it turns a categorical feature into dummy variables.

Feature selection can use document frequency, the chi-square test and mutual information (MI). Feature engineering for text includes identification of numbers, use of N-grams, name entity recognition (NER) and parts of speech (POS) tokenization.

Module 4.3 · Model Training and Evaluation
LOS 4.f

Model Training

Describe objectives, steps and techniques in model training: fitting errors, method selection, data splitting and class imbalance.

Before training: conceptualize the model

  • Before training, define the objective(s) of the data analysis, identify useful data points, and conceptualize the model.
  • Model conceptualization is the iterative planning phase that lays out the process to follow; it is tweaked until the desired results are reached.
  • ML engineers work with domain experts to identify data characteristics and relationships (e.g., the relation between inflation and exchange rates).
  • Once unstructured data has been processed and codified into a structured form such as a data matrix, training is similar to that for structured data.
  • ML seeks to identify patterns in the data set via a set of rules. Model fitting describes how well the model generalizes to new data (i.e., how it performs out of sample).

  • After selecting a method, the researcher specifies the appropriate hyperparameters (e.g., the number of hidden layers in a neural network).

For unsupervised learning, no splitting is needed because there is no labeled training data.

Class imbalance

For a model to discriminate well, it needs a wide variety of training data. Class imbalance occurs when one class has a large number of observations relative to other classes.

Example: in a bond-default model, if the data set holds many high-grade bonds (less likely to default), the model is more likely to predict non-default for a new observation. The training set should mix high- and low-grade bonds.

⬇️
Undersample the overrepresented class

Randomly remove observations of the majority class until the classes are balanced.

⬆️
Oversample the underrepresented class

Add (repeat or generate) observations of the minority class.

Evaluating the Fit of an ML Algorithm

Evaluate the fit of a machine learning algorithm: confusion matrix metrics, ROC / AUC, RMSE, and model tuning (bias vs. variance, grid search, ceiling analysis).

To validate a model we must measure its training performance (goodness of fit). The three techniques below are particularly suited to evaluating binary classification models (RMSE is the exception: it suits continuous predictions).

1. Error analysis — the confusion matrix

Errors in classification problems are false positives (Type I error) or false negatives (Type II error). A confusion matrix shows the results (Figure 4.2, classification of defaulters).

🎯
Precision (P)

Ratio of true positives to all predicted positives. High precision is valued when the cost of a Type I error (FP) is large.

📡
Recall (R)

Ratio of true positives to all actual positives. High recall is valued when the cost of a Type II error (FN) is large.

Precision and recall
precision (P) = TP / (TP + FP)
recall (R) = TP / (TP + FN)
TP true positives, FP false positives, FN false negatives, TN true negatives.
  • FP and FN are both errors but may not be equally important. The trade-off between precision and recall is a business decision and depends on the application.
  • Example: a lender wants to avoid lending to potential defaulters, so it will want to maximize recall (defaulters are the positive class; a missed defaulter is the costly FN).
  • Together, precision and recall determine accuracy, the proportion of correct forecasts out of the total number of forecasts. The F1 score is the harmonic mean of precision and recall.
Accuracy and F1 score
accuracy = (TP + TN) / (TP + TN + FP + FN)
F1 score = (2 × P × R) / (P + R)
Accuracy = all correct ÷ all forecasts. F1 = harmonic mean of P and R.
Exam tip
Type I = false positive → precision. Type II = false negative → recall. To reduce Type I error, raise precision (Module Quiz 4.3 Q6).

2. Receiver operating characteristic (ROC)

Also used for classification, the ROC is a curve plotting the trade-off between false positives and true positives.

TPR and FPR
TPR = TP / (TP + FN)
FPR = FP / (FP + TN)
TPR (true positive rate) equals recall and is plotted on the Y-axis. FPR = FP ÷ all actual negatives, plotted on the X-axis.
  • The area under the curve (AUC) is a value from 0 to 1. The closer AUC is to 1, the higher the predictive accuracy.
  • AUC = 0.50 (a straight diagonal line, Model 1) means the model is randomly guessing.
  • The more convex the ROC curve, the higher its AUC.
  • Figure 4.3 compares three default-prediction models: AUC 0.50 (Model 1), 0.67 (Model 2), 0.90 (Model 3).

Closer to the top-left corner = higher AUC = higher predictive accuracy. The diagonal (AUC 0.50) is random guessing.

3. Root mean squared error (RMSE)

RMSE is useful for continuous predictions such as regression models. It is a single metric summarizing the prediction error in a sample. (Slide: a small RMSE indicates potentially better model performance.)

RMSE
RMSE = √[ Σi=1..n (predictedi − actuali)² / n ]
Square each error, average the squares, take the square root.

Worked example — Dave Kwah’s dividend-cut model

The model classifies whether a company is likely to have a dividend cut next year (cut vs. not cut). In a 78-observation test sample it correctly classified 18 cutters and 46 non-cutters, and it missed 3 companies that actually cut. Then TP = 18, FP = 11, FN = 3, TN = 46.

Actual: CutActual: Not Cut
Prediction: CutTP = 18FP = 11
Prediction: Not CutFN = 3TN = 46
Answers
Precision = 18 / (18 + 11) = 0.62
Recall = 18 / (18 + 3) = 0.86
Accuracy = (18 + 46) / (18 + 3 + 11 + 46) = 64 / 78 = 0.82
F1 = (2 × 0.62 × 0.86) / (0.62 + 0.86) = 1.07 / 1.48 = 0.72
FPR = 11 / (46 + 11) = 0.19

Model tuning — bias, variance and the fitting curve

After evaluation, the model is revised until performance is acceptable.

📉
Bias error

Prediction error in the training data resulting from underfit models. Comes from oversimplified models that do not learn adequately from the training sample.

📈
Variance error

Prediction error in the validation sample resulting from overfit models that do not generalize well.

  • Overfitting is a problem of supervised ML that arises when too many features are included (the model is too complicated).
  • The aim is an optimum trade-off between bias and variance error: neither underfitting nor overfitting.
  • A fitting curve plots training error and cross-validation prediction error against model complexity (more complex = more features).
  • As complexity rises, the model fits the training sample ever more closely and training (bias) error declines, but variance error increases.
  • Regularization reduces model complexity by imposing a penalty on features that do not meaningfully contribute to predictive power. Optimal complexity balances bias and variance error.

Parameters, hyperparameters, grid search and ceiling analysis

TermDefinitionExamples
ParametersEstimated by the model using an optimization technique on the training sampleSlope coefficients in a regression model
HyperparametersSpecified by ML engineers, independent of the training sampleNumber of hidden layers in a neural network; the p-threshold in logistic regression
  • Tuning means altering the hyperparameters until a desirable level of performance is achieved. For each hyperparameter specification, prepare a confusion matrix and compile accuracy and F1 scores.
  • Rather than trial and error (especially with several hyperparameters), use a grid search: an automated process of selecting the best combination of hyperparameters.
  • Ceiling analysis is an evaluation and tuning of each component in the entire model-building pipeline. It identifies the weak link, which can be tuned to improve the model.

Key Concepts — LOS 4.c

Model performance can be evaluated by error analysis. For a classification problem, a confusion matrix is prepared and precision, recall, accuracy and F1 score are calculated. The ROC plots the trade-off between false positives and true positives. RMSE is used when the target variable is continuous. Model tuning balances bias error versus variance error and selects the optimal combination of hyperparameters.
